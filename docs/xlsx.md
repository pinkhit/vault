# XLSX previews — Checkpoint 7, second increment

Use the existing Preview button, then Previous/Next sheet. Visible worksheets are listed in workbook order; hidden/very-hidden worksheets are omitted. Cells and sheet names are escaped React text. Formula expressions are shown literally with `=`, never calculated; empty/shared formula expressions display `[Formula]`. Stored formula results are ignored. Shared/inline rich strings, booleans and raw numeric/error/date values are supported. Sparse rows/columns keep their positions. Microsoft describes the [cell types and shared strings](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-sheets) used by this reader.

The reader supports conventional transitional SpreadsheetML packages with `xl/workbook.xml`, internal worksheet relationships beneath `xl/worksheets/`, and optional `xl/sharedStrings.xml`. It does not reproduce Excel formatting, currency/date styles, merged cells, charts, images or hidden row/column layout. Strict SpreadsheetML, `.xls`, `.xlsm`, encryption and nonstandard part locations remain unsupported. Original downloads are available. Worksheet contents are not indexed; filename/metadata search continues to work. No migration is needed.

## Bounds and authorization

DOCX and XLSX now share the existing [bounded Office ZIP/XML reader](docx.md): 25 MiB source, 256 entries, 64 KiB central directory, 16 MiB declared expansion, depth 64 and 200,000 XML tokens per parsed part. Entries are never unpacked. Duplicate/unsafe paths, symlinks, encryption, ZIP64, archive comments/trailers, DTDs and malformed selected-part checksums fail closed. No new dependency is added.

XLSX further limits workbooks to 32 sheets, workbook/relationship XML to 64 KiB each, and shared-string/selected-worksheet XML to 2 MiB each. Only the requested visible worksheet is decoded. The displayed grid is limited to rows 1–200 and columns A–AF, 4096 bytes per value, and 64 KiB of displayed cell text. Rows/columns outside this window produce a shortened notice; byte/structure limits return an error with download fallback. Huge sparse coordinates cannot allocate a huge grid. XML is checked before decoding bounded structures; cancellation is checked between reads/tokens/rows, not during a single standard-library unmarshal operation. Exact peak memory is unmeasured.

`GET /api/documents/{id}/preview?page=N` uses N as a visible-sheet index for XLSX. Existing session, enabled-user/owner/admin/grant SQL checks, original SHA-256 verification, post-parse authorization recheck and audit requirements apply to every sheet request. The result adds `kind: "xlsx"` and `sheet_name` alongside existing rows/page/pages fields. No request supplies a filesystem path. External relationships are never fetched; fields, macros, links and embedded content are not executed. Active content remains untrusted when downloaded into other applications.
